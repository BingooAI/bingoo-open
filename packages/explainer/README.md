# @bingoo.ai/explainer

Turns a lesson written as JSON into a seekable animated lesson: `frame(program, t)` returns exactly what
should be on screen at second `t`, as plain data any renderer can draw.

You describe a lesson as a document — scenes, elements (text, images, lists, tables, charts, diagrams,
manipulatives), narration with `[[cue:c1]]` markers, beats that fire on those cues, and gates where the
learner has to answer something. `buildProgram` compiles that into a global timeline with a duration;
`frame` samples layout, choreography and content at one instant. The engine has no rAF loop and no mutable
state, so the same `t` always produces the same output: scrubbing backwards un-builds a bulleted list, and
a screenshot at t=12.5 is the same picture every run.

Reach for it when you want lessons that are data rather than code — generated by a model, reviewed and
edited by a human, translated by swapping one `LocaleBundle`, played on the web now and elsewhere later.
`lintDoc` catches the mistakes that otherwise render as silence: a beat targeting an element that does not
exist, a `revealItem` pointing past the end of a list, a chart with no series, a gate with no answer, a cue
with no narration mark in some locale.

## Example

```ts
import { buildProgram, frame, lintDoc, REFERENCE_DOC, REFERENCE_BUNDLE } from '@bingoo.ai/explainer'

const errors = lintDoc(REFERENCE_DOC, [REFERENCE_BUNDLE]).filter((i) => i.level === 'error')
if (errors.length) throw new Error(errors.map((e) => e.message).join('\n'))

const program = buildProgram(REFERENCE_DOC, REFERENCE_BUNDLE, '16:9')
console.log(program.duration, program.gateStarts) // 248.6 [ 117.9, 147.9, 177.9, 218.6 ]

const model = frame(program, 12.5)
console.log(model.sceneId, model.caption)
for (const item of model.items) console.log(item.id, item.type, item.rect, item.pose.opacity)
```

`REFERENCE_DOC` / `REFERENCE_BUNDLE` are a complete worked lesson kept in the package. Swap in your own doc
via `parseDoc` and `parseBundle`. A `RenderModel` carries laid-out items sorted by z, the chrome bands, the
active caption, and the gate spec when the current scene is a gate — the renderer only draws.

## What it does not do

- **No drawing.** No React, no SVG, no canvas, no DOM. The web player is `@bingoo.ai/explainer-web`.
- **No clock.** `createPlayController` advances a `t` for you, but `now`, `raf` and `cancel` are injected by
  the caller. `frame` itself never asks what time it is.
- **No manipulative implementations.** The kits live in `@bingoo.ai/manipulatives`; the engine looks one up
  by kind and resolves it to a `ManipModel` at t.
- **No grading.** Gate answers are graded by `@bingoo.ai/core` (quiz questions, tracing, colouring) and by
  each kit's own check. The schema only says what the gate is and what a pass means.
- **No vendors and no network.** LLM, text-to-speech, image generation and media-library search are
  interfaces under `@bingoo.ai/explainer/providers`; concrete adapters belong in your server app.
- **No translation machinery.** One doc plus one bundle per locale. `collectLocalizable(doc)` hands you
  every authored string keyed exactly the way `frame` reads the override back.
- **No storage.** Documents come in as values; where they live is your problem.

## Purity

No clock, no randomness, no I/O. Time is always a parameter. Per-element phase offsets come from a hash of
the element id, so ambient motion (drifting clouds, swaying trees, a sun that rises with scene progress) is
still a pure function of t. `buildProgram` is safe to memoize; `frame` is cheap sampling on top of it.

## Authoring contract

`contract/` is generated from the engine, never hand-written — it cannot describe a template that moved:

```
pnpm --filter @bingoo.ai/explainer contract   # AUTHORING.md, catalog.json, scene-draft.schema.json, examples.json
pnpm --filter @bingoo.ai/explainer prompt     # PROMPT.md
```

The slot names and character budgets in `catalog.json` are the numbers the layout engine actually uses, and
every few-shot example is run through `checkScene` before it is written. `promptMarkdown`, `templateCatalog`,
`checkScene` and `checkLesson` are exported, so whatever writes a lesson is checked by the code that plays it.

## In the monorepo

The package is `private` and not published to npm. Inside this repo, depend on it with
`"@bingoo.ai/explainer": "workspace:*"`; it exports TypeScript source directly (`./src/index.ts`) with no
build step, so your bundler or runtime compiles it along with your own code.
