# @bingoo.ai/authored-item

Wraps a question, content block or manipulative kit in a thin envelope so the knowledge engine can
select it, grade it, and turn the result into evidence.

You have content in `@bingoo.ai/core` (55 quiz types, 34 content blocks, tracing/colouring) and 63 kits
in `@bingoo.ai/manipulatives`. You have `@bingoo.ai/knowledge-engine`, which selects `Candidate`s and
folds `Verdict`s into mastery. Neither knows about the other: the engine treats content as a black box,
and core has no idea what a skill is. This package is the joint. You add `itemKey`, `skills` and
`difficulty` around an existing payload, and get back the two things the engine wants — a `Candidate` to
pick from, and a `Verdict` + `Submission` after the learner answers.

It also answers the question core never does: **is this primitive measurable, and how is it marked?**
That lives in a registry derived at runtime from core's Zod union and from `INTERACTIVE_KITS`, so a new
quiz type or kit registers itself without anyone editing a list here. Flashcards and reading blocks come
back `measurable: false` and land in exposure, not in the selection bank.

## Example

```ts
import { compileBank, gradeItem, itemSubmission, quizGrader } from '@bingoo.ai/authored-item'
import type { AuthoredItem } from '@bingoo.ai/authored-item'

const item: AuthoredItem = {
  itemKey: 'add-within-10:q1',
  skills: ['math.number.addition.add-within-10'], // Slug, must exist in the skill graph
  difficulty: 1050, // Elo, same scale as learner ability (centred on 1000)
  primitiveKind: 'single', // a core quiz type; use manipKind('tenframe') for a kit
  payload: {
    id: 'q1',
    type: 'single',
    prompt: '2 + 3 = ?',
    choices: [{ id: 'a', label: '4' }, { id: 'b', label: '5' }],
    answerId: 'b',
  },
}

const { bank, exposure } = compileBank([item]) // bank → CandidatePort, exposure → content bank
const response = { type: 'single', choiceId: 'b' }
const verdict = gradeItem(item, response, quizGrader) // { outcome: 1, confidence: 1 }
const submission = itemSubmission(item, response, 'attempt-1', { atMs: Date.now(), latencyMs: 4200 })
// then: toObservations(verdict, submission, ctx, policy) from @bingoo.ai/knowledge-engine
```

For a kit, swap the grader: `primitiveKind: manipKind('base10')`, payload `{ kind: 'base10', target: {
value: 123 } }`, and `manipGrader` dispatches to `checkAnswer` in `@bingoo.ai/manipulatives`. One grader
covers every kit, including kits added later.

`validateItem` / `validateBank` check the anchoring invariants before any of this: no item without a
skill, no skill outside the graph, no duplicate `itemKey`, nothing marked measurable that has no way to
be marked.

## Namespacing

Kit and quiz names collide — `tenframe`, `numberline`, `clock`, `partwhole` are both a question type
(auto-key) and a kit (checked state). Kits are therefore registered under `manip:`, content blocks under
`block:`. Use `manipKind(k)` and `blockKind(t)` rather than writing the prefixes by hand; a bare
`'tenframe'` always means the quiz type.

## What it does not do

- **No content schemas.** Question and block shapes, and `gradeQuestion`, belong to `@bingoo.ai/core`.
  `payload` is opaque here — this package never parses or edits it beyond writing resolved media ids.
- **No mastery maths.** BKT, Elo, forgetting, certification are `@bingoo.ai/knowledge-engine`. This
  package stops at `Verdict` and `Submission`.
- **No kit rendering or checking logic.** `checkAnswer`, kit params and labels are
  `@bingoo.ai/manipulatives`; `manipGrader` only dispatches.
- **No item authoring.** Deciding which primitive suits which knowledge point is `@bingoo.ai/authoring`
  and `@bingoo.ai/content-gen`. `listPrimitives` and `listBlockTypes` exist to feed those with the real
  catalogue instead of a hardcoded shortlist.
- **No media I/O.** `mediaTargets` says which slots need an image, audio or video and gives a stable
  `dedupKey`; `resolveMediaTargets` orchestrates, but the actual search/vision/TTS call is injected by
  the host.
- **No persistence, no idempotency.** `attemptId` is generated by the caller.

## Purity

No clock, no randomness, no I/O. Times (`atMs`) are always passed in. `resolveMediaTargets` is async
only because the resolver you inject is; the package itself makes no calls.
